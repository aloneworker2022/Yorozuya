## 1 願景

真實 Todo 驅動的成人 PWA：玩家把現實待辦丟進來 → 完成賺金幣 → 召喚魅魔 → **在玩家自己的房間裡**陪伴、聊天、身體互動、關係慢慢長大。（確）

- **房間系統是核心**（確）：名冊付費「召喚」＝把她帶進主畫面中下方的像素房間，長按她聊天／互動。舊的遠距感應聊天、淫紋全螢幕聊天、看板打牌、主線約會入口都已退出玩家主路徑。
- **手機優先、網頁為主**（確）：`android-app/` 只是 WebView 外殼，連使用者自己的 FastAPI 伺服器。
- 一句話方向（沿用交接書）：**玩家帶著自己的生活來找她，她也帶著自己的生活來找玩家；在玩家的房間裡慢慢形成有延續的關係。**

## 2 目前方向與優先順序

1. **房間陪伴的品質**：聊天要接得住、有個性、有延續（互相認識 `playerNotes`、傾聽、生活瑣事、關係分階口吻）。（確／現）
2. **房間為唯一關係真相**：感情與階段一律走房間 11 階規則；主線程式只換算顯示、不覆寫。（確／現，2026-10-02）
3. **個性逐步揭露**：名冊妹子的人設整份帶進房間，依房間關係階逐步放進 prompt。（確／現）
4. **身體／說話／失神規則穩定**：一般情況正常說話，只有失神、痙攣、餘韻、正被刺激才崩。（確／現）
5. 退役系統保持乾淨關閉（旗標），不要順手復活。
6. 之後（待點名才做）：妻子打工／活動（§4 of ROOM-RELATIONSHIP-EFFECTS）、未來 NTR（用忠誠）、房間版約會、番茄鐘陪伴、多人同房、主動聊天。

## 4 核心循環

```
現實待辦 → 委託（發現／接下／完成）→ 金幣
   → 祭品商店 → 獻祭召喚 → 名冊（當場織出形體）
   → 名冊「召喚（2～4 金）」→ 房間陪伴：長按聊天／動作
        → LLM 判定 接住 +1／冒犯 −1、身體事件加感情 → 房間 11 階關係
        → 花束告白（女友）／戒指求婚（妻子）
   → 停留到期 → 她回自己的住處，在外面過日子（打工／亂逛／朋友），再召喚回來
   → 獻祭魅魔 → 擴充天賦（名額、格數、報酬…）
```

## 5 關係模型：房間 11 階（唯一真相）

| key | 顯示 | 感情門檻 | 段（`s.stage`） |
|---|---|---|---|
| `stranger` | 陌生 | 0 | stranger |
| `acquaintance` | 普通 | 15 | stranger |
| `friend` | 朋友 | 35 | friend |
| `close_friend` | 親密好友 | 60 | friend |
| `girlfriend` | 女友 | 100＋**花束** | girlfriend |
| `passionate` | 熱戀 | 140 | girlfriend |
| `lover` | 愛人 | 180 | girlfriend |
| `wife` | 妻子 | 230＋**戒指** | wife |
| `devoted_wife` | 貼心妻子 | 280 | wife |
| `obedient_wife` | 順從妻子 | 330 | wife |
| `pathological_wife` | 病態妻子 | 380 | wife |

- 存檔：`s.roomStage`＝真相（11 階），`s.stage`＝它換算出的主線四階（給舊程式讀）。量條與標籤用 `displayStage()`。
- 自動升降依感情，但**不會自動跨進女友**（停在親密好友）、**不會自動跨進妻子**（停在愛人）；降階有 **5 點緩衝**；`stageLock`（房間除錯跳階）優先。
- 帶內軟升（女友→熱戀→愛人、妻子→貼心→順從→病態）用 `datingUpPending`／`wifeUpPending` 讓房間演極淡銜接，不講階段名。
- 告白：親密好友＋感情 ≥100＋花束 → 女友（感情不歸零，補到 ≥100）。求婚：女友／熱戀／愛人＋戒指 → 妻子（感情補到 ≥230）。
- 實作對齊：房間 `syncStage`（`test_room_summon.js`）＝主線 `roomSyncStage`／`normalizeGirlStage`（`app.js`）。**改一邊就要改另一邊。**

## 6 感情規則（房間）

- 每句玩家話由 LLM 判定（`judgeUser`）：**接住 +1**（清防備）、**冒犯 −1**（設防備 `guard`）、其他 0。
- 身體事件：接近高潮 +1、痙攣 +2、射精 +2；外面朋友肉體事件有自己的小幅增減。
- 主線 `applyAffection`：整數加減、**不乘稀有度**，結果走同一套 11 階規則；只在細階上升時 toast。
- 房間回寫（`applyRoomProgressData`）直接寫 `roomStage`／`affection`，並把 `lastChatDay` 設為今天（房間聊天＝有聊天）。
- 沒有任何「沒聊天／沒約會」扣分，也沒有因低感情離開或被奪走。

## 7 個性逐步揭露（`REVEAL_AT`）

名冊妹子進房（`buildRoomGirlFromSuccubus`，`app.js` 與沙盒兩份）整份帶入 `archetype／catchphrases／reactions／stats（主動・害羞・忌妒・忠誠）／kinks／kinkMeta／chrono／likes／dislikes／hobbies／contrast`。沙盒生成的妹子本來就有整份。**進 prompt 的部分**由 `test_room_summon.js` 的 `REVEAL_AT` 決定，兩條路徑同一套：

| 房間階 | prompt 會有 |
|---|---|
| 陌生 | 個性底色、語氣、口頭禪、主動／害羞的表面舉止 |
| 普通 | ＋喜歡的東西 |
| 朋友／親密好友 | ＋討厭、興趣、一般怪癖、當下心情的反應、作息 |
| 女友／熱戀 | ＋吃醋行為（女友前完全不寫）、所有心情的反應 |
| 愛人以上 | ＋性癖（強度沿用 `kinkRevealLines` 分級）、性慾傾向、色情類怪癖（確：性癖在愛人揭露） |

- 性癖口頭禪：順從妻子起。生活旁白 `personaBlurb` 也是愛人以上才帶性癖。
- **稱呼「老公」只限妻子以上**（妻子／貼心妻子／順從妻子／病態妻子）。女友～愛人：用名字、「你」或已確認的小名（`playerPet`），prompt 明寫禁止叫老公。個性家族提示（`personalityStageLines`）的愛人檔是獨立一檔，不含老公。（確，2026-10-02）
- 除錯：`RoomCompanion.debugPrompt()` 回傳目前對話的 system prompt。

## 8 身體／說話／失神規則（房間）

- **一般情況正常說話**：性奮、性慾再高，她也盡量鎮定、用完整句子（頂多臉紅、心不在焉、直白說想要）。（確）
- **只有**以下才讓說話崩（嬌喘、斷句、說腿軟）：`stun_speech.speechMode()` 判為 **痙攣／餘韻／失神（有效失神 ≥75）／正被刺激**。
  - 正被刺激＝`body_state.stimulationState()`：陰道／後穴插著手指、跳蛋、假陰莖、小黃瓜、陰莖，或本回合正被摸性感帶；閒聊要有動手動詞（摸／插／揉…）才算（`bodyState.touchVerb`）。
  - 摟腰、摸臀、大腿、輕摸胸、親嘴＝只允許一瞬短反應。
- **沒刺激時失神上限 69**（`UNSTIM_STUN_CAP`，低於失神 75 與痙攣門檻 70）。刺激中累積的失神記在 `bodyState.stunCarry`，停手後每秒 −0.5、每句回覆 −8。高潮中繼續調戲（`climaxTease`）算正被刺激。
- 痙攣：失神 ≥70 時被刺激進入，持續 `SPASM_MS`（10 分鐘）。
- **侵犯值**（`invasion.js`，0–100，動作依關係階倍率與失神抑制累加；滿 100 她逃離房間並清 0、可再召喚）。衰減只有兩條（2026-10-02）：
  - **每句閒聊回覆 −1～2**（`decayInvasion`，非動作的玩家台詞）。
  - **時間衰減：每滿 20 分鐘真實時間 −1～2**（`decayInvasionByTime`）。時間戳 `bodyState.invasionDecayAt` 跟著存檔，重新整理／換裝置不重置；關掉很久就補 floor(經過/20分) 次、最多扣到 0；侵犯從 0 開始累積時從當下起算；時鐘在未來（裝置時差）則從現在重算。閒置 tick（約 5 秒）只負責觸發檢查，不再每次扣。
- 其他房間狀態照現行程式：開放度（`openness.js`，解鎖動作）、調戲階梯（`tease.js`）、性奮冷卻、器官／精液狀態（`body_state.js`）。

## 11 開發慣例

1. 先 `git pull`；**使用者的程式是權威**，不要覆蓋使用者本機或遠端的新工作；不要 force push。
2. 改 `web/` 的 JS 一定 **bump 版本**：`index.html`／`test_room.html` 的 `?v=` ＋ `sw.js` 的 `CACHE`（每次 +1）。
3. 改 `server/*.py` → 使用者要**重啟 uvicorn**。
4. 每個驗證過的里程碑 commit＋push 到 `origin/grok-2026.10`。
5. 在手機尺寸驗證（390×844、mobile UA，`userAgentData.mobile=true`，否則房間不會回寫）；看 console 無錯；不要只過語法檢查就說互動正常。
6. **檢查階段換算**：任何寫 `stage` 的程式都要經過 `normalizeGirlStage`；不要把房間細階直接塞進 `s.stage`，也不要用主線規則改 `roomStage`。
7. 退役系統只用旗標關，不刪大段程式；不要順手打開。
8. 一次交付一小步，讓使用者看效果再修。

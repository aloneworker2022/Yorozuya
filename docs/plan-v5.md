## 1. 核心迴圈

```
   做委託 ──→ 金幣 ──→ 買祭品 ──→ 獻祭召喚 ──→ 魅魔(當場織出形體)
      │                                              │
      │  每次操作各擲一次                             │ 付金召喚為看板娘(限時)
      ↓                                              ↓
   淫紋亮起 ←──────────────────────────────── 她在店頭,會找你說話
      │                                              │
      ↓                                              ↓
   聊天(免費)                                 別的召喚師也看得到她
      │                                              │
      ↓                                              ↓
   情感 ↑ → 升階 → 她管得動你(點名)      纏上 → 召喚走 → 交配環 → 娶走
      │                                              │
      └──→ 約會(5 金)→ 情感 ↑↑                   └──→ 約會撞見 → 有機會搶回來
```

- **委託 = 現實中的待辦事項**(與 cthulhu-note 同源;動機翻轉:慾望驅動而非懲罰驅動)
- **金幣 = 唯一貨幣**,委託是唯一收入來源
- **魅魔 = 金幣的消耗出口**:祭品、看板娘、約會、獻祭費
- **時間壓力來自別人**:你不理她,別的召喚師會理

## 2. 委託系統

### 2.1 狀態機

```
[Lv0 發現 +0~2金] --承接--> [Lv1 已承接] --開始執行--> [Lv2 執行中] --完成--> [+1~3 金]
    |                          |                          |
   推掉                       推掉                    超時(24h)
    ↓                          ↓                          ↓
  [刪除]              [刪除,-1~3 金]        [-1~6 金,退回 Lv1 已承接]
```

| 項目 | 值 | 來源 |
|---|---|---|
| 發現獎勵 | 每日前 **10** 次 +0~2 金 | `DISCOVER_BONUS_CAP` |
| 執行期限 | **24 小時**,由「開始執行」手動觸發 | `QUEST_HOURS` |
| 執行中上限 | **1 + 「執行中格數」擴充等級**(初始 1 格) | `execCap()` |
| 完成報酬 | `randInt(1+lv, 3+lv)`,lv = 「完成金額」擴充 | `rollReward()` |
| 超時違約 | -1~6 金,**退回已承接池**(現實待辦不會消失) | `failQuest()` |
| 推掉已承接 | -1~3 金(信用受損) | `drop()` |

- **金幣可為負**(欠萬事屋的債)。負債時不可召喚、不可約會,只能做委託還債
- 負債期間需求時鐘**照走**——冷落的後果是被別人接手,這是刻意設計
- 睡眠時段委託照常運作:倒數不暫停、可開始、可完成

### 2.2 每次操作都會驚動她

發現 / 承接 / 開始執行 / 完成——**每一次操作都對此刻在店頭的每位看板娘各擲一次淫紋**(第 3 章)。
你做事她就找你說話,你不做事店裡就安安靜靜。這是整個迴圈的黏著點。

### 2.3 設計哲學:誠實系統與短衝刺

- 委託定位為**一口氣做完的短衝刺**(數十分鐘~數小時)。跨數日的大事不是一件委託,是委託的**來源**,必須拆小
- 期限到了做不完,正確反應是**推掉重編再承接**,不是硬吃違約金
- 倒數由玩家手動觸發,系統**不防作弊**(先做完再按開始→秒完成,技術上可行)。玩的是自己的人生,騙的也只是自己的魅魔

### 2.4 委託是唯一「她碰得到你人生」的介面

`state.quests` 裝的是玩家真實人生的待辦。AI **只能盯清單裡已經有的一件,不能派新的**(7.2 點名機制)。
嘴上順口講的小事留在台詞裡,不進系統——用 AI 幻覺污染真實待辦是不能開的口子。

## 3. 淫紋:她想跟你說話

**淫紋不是入場券,是一盞燈。** 亮了代表「這位看板娘有話要跟你說」,點開就聊,不花任何資源。

### 3.1 判定

每次委託操作 → 對每位在場看板娘各擲一次她自己的出現率:

| 稀有度 | N | R | S | SS | SSR |
|---|---|---|---|---|---|
| 出現率 | 1/4 | 1/3 | 2/5 | 1/2 | 2/3 |

- 「淫紋機率」擴充每級 **+5%**,上限 90%
- **不判定**的情況:睡眠時段、她被召喚走、她已經有紋在等你、她正在打字、這場對話還沒聊完
- 中了就是**一場全新的對話**:訊息串上劃一道場景線,她從新話題開口

### 3.2 一場對話怎麼跑

```
紋亮 ──→ 她的開場白在背景寫(代工佇列)
  │
  ├─ 寫好了 → 點開秒顯示她的話 → 你回一句 → 立刻跳出,她慢慢打字
  └─ 還沒好 → 點開「她在等你開口」→ 換你先說(零等待)
                                        ↓
                              她回完 → 紋再亮 → 你再進來看
                                        ↓
                          聊滿 2~4 來回 → 收尾鈕 → 結算情感 -1~+2
```

- **進場零等待**是硬性要求:任何情況下都不讓玩家對著轉圈等生成
- 一場對話**跨多次進出**,回合數記在她身上(`s.chatSess`);擱置超過 30 分鐘自動作廢,不讓沒聊完的舊對話把紋鎖死
- 中途離開不結算;整場聊完才結算一次
- 沒設 AI 模型(或連續失敗 3 次)→ 罐頭台詞保底,循環照樣跑得動

## 4. 召喚系統

### 4.1 祭品商店(每日進貨)

| 項目 | 值 |
|---|---|
| 每日進貨 | **2 + 「商店祭品」擴充**(初始 2 人) |
| 單價 | 5~30 金,每人獨立擲骰 |
| 刷新 | 每日重置,前日未售出的存貨消失 |
| 庫存 | 買下存入「地牢」,永久保存、可累積 |

獻祭效果只看**人數**不看單價 → 理性玩家等便宜貨,每日開店看價即每日簽到動力。

### 4.2 獻祭召喚

一位一位獻祭(每位都有 AI 生成的旁白演出),最多 6 人,獻完按「召喚」。人數換算成**幸運值**:

| 獻祭人數 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| luck | 0 | 18 | 35 | 55 | 75 | 92 |

### 4.3 魅魔生成(原型骨幹 + 評級抽卡)

`content/girl_gen.js` + `content/persona_pools.json`。**稀有度不是直接擲的,是算出來的**:

1. 抽原型(archetype)決定人格骨幹:語氣、口癖、情緒反應、主動性、羞恥心
2. 職業 / 性慾傾向 / 體型 / 罩杯 / 眼睛各自**加權抽一個帶評級的項目**(luck 把機率往高階推)
3. 抽 1~3 個特殊屬性(同類不重複,luck 拉高稀有度)
4. 總評分 = 各項評級的 `平均 × 0.58 + 最高 × 0.42`,小數部分當進位機率 → N / R / S / SS / SSR

> 有一項頂級就明顯拉高總評;獻越多人 luck 越高,SSR 真的開得出來。
> `SUMMON_TABLE`(v4 的人數→稀有度機率表)只在池子載入失敗時當退路。

生成結果包含:名字、年齡(**18~33**)、職業與生涯服裝、背景故事、作息四時段、外貌五軸(臉/眼/嘴/髮型/髮色)、
個人衣櫃 6 套、喜好/討厭/興趣、生理時鐘、近況、反差、性慾傾向、天賦(8 軸之一或「取消召喚師」)。

- **名冊名額 = 1 + 「名冊名額」擴充**(初始 1 格)
- 職業池的「女高中生」在 **NSFW 模式下不參與抽卡**(`MINOR_OCC`)

### 4.4 召喚當下就織出形體

v4 的「首夜成形」已取消。生圖能用時(ComfyUI 或 Grok),**召喚結果卡會當場等她的全身像織出來**,
織完才給「接受契約」;生不出來(沒設定生圖)才退回「讓她今晚做個夢吧」的舊敘事。詳見第 10 章。

## 5. 看板娘:限時、付費、可複數

**只有在店頭的看板娘會亮淫紋、會講委託台詞、會出現在主畫面。** 沒召喚看板娘的話,店裡空無一人。

| 項目 | 值 |
|---|---|
| 費用 | 第 1 位 **1 金**;第 n 位(n≥2)= `50×(n−1) − 「召喚減費」擴充`,地板 2 金 |
| 時長 | **1 + 「看板娘時長」擴充** 小時 |
| 到期 | 自動解除,**不提醒、不顯示剩餘時間**、無自動遞補 |
| 在任效果 | 她的天賦暫時加到玩家身上(多位可疊,每位 +1) |

- 到期判定由**伺服器世界時鐘**權威判定(關螢幕也照走),手機同步時套用
- 她在店頭時**不會被別的召喚師纏上**——把她留在身邊就是保護她
- 全部到期後,背景顯示最後一位看板娘的「休息中」剪影

### 5.1 罐頭反應與委託台詞

- **罐頭反應**(不打 AI、不花錢):完成委託 → 開心;違約 → 生氣;剩 20% 時限 → 催你;睡眠時段停用
- **委託台詞**:背景代工預生每位看板娘 3 句「看著你的待辦想說的話」,點她就冒一句;委託狀態一變舊台詞全作廢

## 6. 魅魔養成

### 6.1 稀有度效果

| 稀有度 | 情感成長倍率 | 需求(維持條件) | 淫紋出現率 | 被召喚師纏上 |
|---|---|---|---|---|
| N | ×1.0 | 每 3 天至少聊天 1 次 | 1/4 | 1/5 |
| R | ×1.1 | 每 2 天至少聊天 1 次 | 1/3 | 1/4 |
| S | ×1.2 | 每天至少聊天 1 次 | 2/5 | 1/3 |
| SS | ×1.35 | 每天聊天 + 每 5 天約會 1 次 | 1/2 | 1/2 |
| SSR | ×1.5 | 每天聊天 + 每 3 天約會 1 次 | 2/3 | **必定** |

> **稀有度是雙面刃**:越稀有的話越多、成長越快,但也越容易被別的男人盯上。
> 「每天」以睡眠結束時刻為日界(醒來 = 新的一天)。

### 6.2 互動

| 互動 | 費用 | 情感 | 其他效果 |
|---|---|---|---|
| 聊天 | **免費**(要有淫紋亮著) | 整場結算一次 **-1~+2** | 滿足需求 |
| 約會 | **5 金**,每隻每日上限 2 次 | **+1~+5** | 滿足需求;飢渴 -40 |

- 情感變化一律由**遊戲核心擲骰**,與 AI 輸出內容無關
- 約會地點自 30 個情境池隨機抽 5 個給玩家選,影響場景描述與台詞,**不影響數值**
- **睡眠時段互動全面關閉**

### 6.3 需求、警告與 NTR(冷落線)

- 需求未達成:**每逾 1 天,情感 -3**(每隻獨立計算)
- 情感 ≤ **-7**:警告狀態(名冊卡狀態燈)
- 情感 ≤ **-10**:
  - **陌生階段**:直接離去,永久消失(還沒有羈絆,無戲可演)
  - **朋友以上**:進入 NTR 狀態——名冊卡轉灰、互動鎖定、情感凍結於 -10、需求時鐘停止
    - **贖回窗口 7 天**,贖金 = 該階段門檻(朋友 30 / 女友 90 / 妻子 180 金)→ 她回來,情感歸 0,階段保留
    - 窗口過期未贖:**永久消失**(含全部對話紀錄)

> 這條線是「你完全不理她」的結局。第 8 章的召喚師系統是另一條線:**你有在理她,但別人理得更多**。

### 6.4 關係階段

| 階段 | 情感門檻 | 解鎖 |
|---|---|---|
| 陌生 stranger | 0 | 召喚即是。防備狀態生效,衣櫃 0 套 |
| 朋友 friend | 30 | 點名(50%)、人設欄位主動揭露、衣櫃 1 套 |
| 女友 girlfriend | 90 | 點名必定 + 追問、性慾傾向注入(NSFW)、衣櫃 3 套 |
| 妻子 wife | 180 | 直接交代不追問、拖著沒做會失望、衣櫃 6 套 |

階段為**里程碑,不回退**;但情感照樣會掉到 -10 → NTR(妻子也會被搶,而且最貴)。

## 7. 她是怎麼演出來的

完整規格見 **`docs/relationship-axes.md`**;以下是機制面摘要。

### 7.1 四階段 = 六條可執行行為軸

稱呼他 / 誰先開口 / 自我揭露 / 對他的要求權 / 界線在哪 / 你的身體,再加一條回覆長度。
**寫的是「你有沒有立場說」而不是「你語氣要多重」**——否則會跟人格設定撞車。

同一份人設,四階段**注入的欄位不同**:陌生階段完全不注入近況/反差/生理時鐘,
喜好與背景只在被問到時說。這比多寫幾行形容詞有效得多。

### 7.2 點名機制(要求權的載體)

| 階段 | 點名機率 | 後續 | 做完 | 沒做 |
|---|---|---|---|---|
| 陌生 | 不點名 | — | — | — |
| 朋友 | 50%,語氣是吐槽 | 不追問 | +1 好感 | 無所謂 |
| 女友 | 必定 | 下次聊天追問做了沒 | +2 好感 | 鬧脾氣(不扣) |
| 妻子 | 必定,直接交代 | 不追問(當他會做) | +2 好感 | **隔日 -1 好感**(只扣一次) |

- **遊戲挑件,AI 只演**:剩時間最短的執行中 > 承接最久沒動的 > 隨機一件發現池的
- **嘴上答應不算數**:真的把那件委託做完才給好感

### 7.3 防備狀態(界線的載體)

玩家自由輸入,關鍵字比對測不到越界——**所以讓她自己回報**:
陌生階段的 prompt 要求第 2 行輸出 `#越界` / `#正常`,而 app 取她的回覆本來就只取第一行。
零額外呼叫、零延遲、零顯示風險。

- 收到 `#越界`:`hits++`,冷 4 則玩家訊息;期間她更短、更冷,而且**必須講出來**讓玩家知道踩線了
- **不扣好感**——探索期的玩家會亂試,扣數值會勸退。冷四則已經夠痛
- 升到朋友以上,整個防備狀態作廢

### 7.4 飢渴(身體軸的動態層)

她不是被搬了位置,是**被改造過**。這是一層會起伏的身體狀態,**不影響任何存活機制**。

| | |
|---|---|
| 累積 | 每小時 +4(約 25 小時滿) |
| 檔位 | `<35` 平靜(**完全不注入 prompt**)/ `35~71` 上來了 / `≥72` 很難受 |
| 他越界調戲 | **+15** |
| 約會結束 | -40 |

**越界 +15 是整套設計的樞紐**:玩家調戲她 → 她擋回去、進防備(更冷),同時飢渴上升(更難受)。
**她最兇的時候正好是她最難受的時候**——被強迫感從這裡來,不是從她罵得多兇來的。

詳細頁在「上來了」以上時多一行狀態文字,**不顯示數字**——她自己都不肯承認,不會有儀表板。

## 8. 召喚師與交配環(★ 核心之一)

**她不是只屬於你的。** 別的召喚師也會盯上她、召喚她走、一步步把她變成自己的人。
整套判定與紀錄由**伺服器權威運算**(`server/sim.py`),手機關螢幕、離線都照跑。

### 8.1 三個階段

```
未纏上 ──每 30 分一輪(稀有度機率)──→ 纏上(綁定一位召喚師,抽 4~10 個性趣給這對)
                                          │
                                    每 30 分一輪(稀有度機率)
                                          ↓
                                    被召喚走(約會 1 小時 / 召喚 2~5 小時)
                                          │
                                  每小時生 3~5 個「act slot」
                                          ↓
                              每個 slot:擲交配(1/抵抗)→ 中=交配3則 / 沒中=猥褻1則
                                          │                    每個 slot 抵抗 −1
                                          ↓
                                    交配推進交配環(見 8.2)
```

- **她當看板娘時不會被纏上**(在你身邊 = 受保護);NTR 中的也不判
- 解召喚後隔一輪才會再判定

### 8.2 交配環(她對他的關係階段)

| 階段 | 名稱 | 基礎抵抗(交配機率 = 1/抵抗) | 推進條件 |
|---|---|---|---|
| ⓪ | 強烈嫌惡排斥 | 40 | 交配 2 次 |
| ① | 嫌惡抗拒 | 20 | 交配 3 次 |
| ② | 抗拒冷淡 | 10 | 交配 5 次 |
| ③ | 抗拒 | 10 | 交配 5 次 |
| ④ | 偶爾互動 | 5 | 每次交配 1/5 她主動告白 |
| ⑤ | 女友 | 1(必定) | 累積 20 次 → 她主動解開魔法環 |
| ⑥ | 妻子 | — | 解環後每次交配 1/2 懷孕 → **娶走** |

- **抵抗每個 act slot −1,最低 1**:她被召喚得越久,抗拒越薄
- **懷孕 = 永久消失**:她脫離魅魔身分跟他走,名冊除名,只留一行日誌
- **SFW 模式只有猥褻,不交配、不推進、不會失去她**——交配環是 NSFW 專屬的失去機制

### 8.3 玩家看得到什麼、能做什麼

| 管道 | 費用 | 看到 | 搶回機率 |
|---|---|---|---|
| 她被召喚走時去**約會** | 5 金(照付) | 觀戰他們的實況,一次 1~2 則 | **1/10** |
| 聊天時按**詢問** | 免費 | 她坦白 1~2 則你沒看過的紀錄 | — |

- **詢問的代價**:她被逼著全招,情感 **0~-1**;完全沒有紀錄可說時她會生氣離開(-1)
- 搶回成功 = 她掙脫召喚回到你身邊,原本付費的那場約會接著開始
- 紀錄文字由背景代工佇列慢慢生成;生好的才浮出來給看
- 詳細頁只顯示「她此刻正被召喚中」,**不顯示過去的紀錄**——要靠撞見或詢問

## 9. 獻祭魅魔與擴充系統

### 9.1 八軸擴充

玩家的永久成長全部在這裡。取得方式:**看板娘在任時暫時 +1**(她的天賦)或 **獻祭她永久獲得**。

| 軸 | 效果 |
|---|---|
| `exec` 執行中格數 | 上限 = 1 + lv |

| `offering` 商店祭品 | 每日進貨 = 2 + lv |
| `roster` 名冊名額 | 名額 = 1 + lv |

### 9.2 獻祭

## 10. 織夢:圖像生成

**「織夢」現在是敘事名詞,不是排程。** 生圖在需要的當下就跑,不等夜間。

### 10.1 兩條路

| 供應商 | 說明 |
|---|---|
| **ComfyUI** | 顯卡那台的本機 GPU,SD tag,召喚三連拍 |
| **Grok Build** | 伺服器跑 `grok -p` 無頭 CLI,中文敘述 |

### 10.2 召喚三連拍(ComfyUI)

| 種類 | 出圖 | 去背門檻 | 用在 |
|---|---|---|---|
| `head` 大頭照 | 256×256 | 55% | 名冊縮圖、聊天名字旁的頭像 |
| `half` 半身 | 832×1216 | 72% | **聊天立繪**(站在對話框上方)、詳細頁 |
| `full` 全身 | 832×1216 | 72% | **看板娘背景板**、召喚結果卡 |

- **三張同一個 seed**(取自人設雜湊)= 同一張臉;重生也還是同一個人
- **召喚只等 `full`**,另外兩張在玩家讀結果卡時背景補完
- SD 畫不出 alpha,所以是「要一塊平背景、生完再摳掉」(`server/cutout.py`),三道閘門任一不過就原圖不動
- 摳不掉時**三個地方講得出原因**(設定頁 / 詳細頁 / testword)——不讓失敗靜靜消失

### 10.3 人設 → SD tag

CLIP 對中文幾乎沒有有效編碼,所以 ComfyUI 這條把抽卡欄位翻成**純英文 Danbooru tag**(`server/sdtags.py`)。

- **精確查表,不做模糊比對**:對不上就丟掉該欄位並回報(池子被改過當場看得到),不把中文混進 prompt 假裝有效
- **臉分五軸各 18 項**:只寫「大眼睛、長直髮」畫不出同一個人
- **特殊屬性壓過一般欄位**:抽到「巨乳」而人設寫 B 罩杯時,巨乳說了算(整個換掉,不是疊加)
- **她們不是魔物**:角/翅膀/尖耳/succubus 一律進 negative,沒有開關。被改的是感覺與慾望,那些畫不出來,也不該用長角代替
- **年齡是必填的**:不給年齡,模型畫出來的歲數會隨機漂

### 10.4 服裝:生涯服裝 + 個人衣櫃

| 維度 | 來源 | 誰決定 |
|---|---|---|
| **生涯服裝** | 職業 | 抽到什麼職業就是什麼:女高中生=水手服,護理師=護士服 |
| **個人衣櫃** | 個人品味,一次抽滿 6 套 | 她自己;依關係解鎖 0 / 1 / 3 / 6 套 |

- **立繪預設畫生涯服裝**;換衣服會把三張立繪全部重織(舊圖穿的是舊衣服)
- 聊天的人設描述與立繪走**同一套規則**,她講的跟畫的才是同一身衣服
- ⚠ **目前沒有玩家入口**:詳細頁精簡時把衣櫃選擇器收掉了,只剩 `DBG.wearOutfit()`(見 14.1)

### 10.5 GPU 換班

同一張卡不能同時餵 Ollama 與 ComfyUI,所以「誰現在能用 VRAM」由 RP5 即時仲裁(`server/comfy.py`):

| 要跑什麼 | 進去前先做的事 |
|---|---|
| 聊天 | `POST <comfy>/free`(卸 ComfyUI 的模型) |
| 生圖 | 掃 Ollama `/api/ps` → 逐一 `keep_alive: 0` |

- **不寫死模型名**:掃到什麼卸什麼
- **黏著**:只有「換邊」那次付卸載成本,連續聊十句或連生十張都不卸
- **卸不掉不擋路**:寧可讓後手自己 OOM 報錯,也不要因為卸載失敗把玩家的聊天卡死

## 12. 技術架構

```
┌─ 瀏覽器(PWA,單一 HTML + 單一 module)
│   ├─ 遊戲核心:委託/金流/召喚/情感/需求/NTR/淫紋/看板娘/演出
│   ├─ 存檔唯一寫入者;localStorage 只作離線快取
│   ├─ import content/persona_builder.js + girl_gen.js   ← 廠商替換點
│   └─ 對伺服器:存檔 / 代工佇列 / 生圖 / 召喚師同步
│
├─ RP5 遊戲伺服器(FastAPI + SQLite,常駐)
│   ├─ 靜態伺服 + assets/
│   ├─ 存檔 API(版本號 409 防舊裝置蓋新檔)
│   ├─ 代工佇列 /api/gen:手機下單 → 伺服器排隊跑 LLM → 手機收貨
│   ├─ 生圖 /api/imggen:ComfyUI 或 Grok Build
│   ├─ 世界時鐘(每 30 秒):召喚師模擬 + 看板娘到期 + 委託逾期 + 跨日;每 10 分心跳日誌
│   └─ GPU 仲裁 comfy.py
│
└─ Windows(顯卡)
    ├─ Ollama 常駐(聊天)
    ├─ ComfyUI 常駐(生圖)
    └─ desktop/ 系統匣程式:養著 ComfyUI 不死,桌面不留視窗,設定頁走本機網頁
```

### 12.1 權責切法(這套的核心設計)

| 誰 | 負責 |
|---|---|
| 伺服器 | 判定「時間到了沒」、算召喚師模擬的數字與事件 |
| 手機 | 所有遊戲後果的邏輯、所有存檔寫入 |

伺服器把判定結果寫成 **outcome** 丟給手機套用(`kanban_expired` / `quest_due` / `day_rollover` / `entangled` / `married`),
**後果邏輯只在 JS 裡一份**,不會有 Python↔JS 規則分歧。所有 outcome 具冪等性,重複套用無害。

### 12.2 代工生成

手機下單(key + messages)→ 伺服器背景跑 → 手機輪詢收貨。
**手機關螢幕、切 app、瞬斷都不中斷生成。** key 是內容狀態指紋,狀態變了 key 就變,舊單自然作廢。

用在:她的下一句話、觀戰紀錄文字、看板娘委託台詞、獻祭腳本。

### 12.3 崩潰自癒

PWA 快取不同步(app.js 與它 import 的模組版本不一致)會把 app 炸成無法互動的空殼。
啟動 8 秒內偵測到 JS 例外或資源載入失敗 → 註銷 SW + 清光快取 + 硬重載(最多 2 次)。
另有「存檔載入失敗 → 用臨時全新狀態開啟、絕不寫回」的保護,以及設定頁的「強制更新」「全部重來」兩顆自救鈕。

### 13A.1 為什麼要改

### 13A.2 一句話

> 委託養金幣與牌庫 → 召看板娘（可陪伴、可碎嘴）→ 深度只用牌；無自由聊天；高級卡用則碎；虐只開門給鍊；出手 N 由女子關係決定。

| 玩家自由輸入 | **話術卡**（創角 10 選 1；商店可續買，不碎、偏貴）＋出卡短 AI |
| 淫紋機率隨稀有度 | 氣泡機率 **寫死 15%**，不隨成長改 |
| 看板 = 聊天與天賦載體 | 看板 = **在場陪伴 + 氣泡 + 牌桌 session + 天賦**；可不打牌 |

## 15. 經濟平衡

**⚠ 這一章是現況記錄,不是配平結果。** v4 的試算(完成 +1~24 金)已經作廢,v5 的數字尚未重新配平。

| 項目 | 值 |
|---|---|
| 收入 | 完成 1~3 金 + 發現 0~2 金(每日前 10 次) |
| 初始格數 | 執行中 **1 格**、名冊 **1 格** |
| 支出 | 祭品 5~30 金 / 人・約會 5 金・看板娘 1 金(第 2 位起 50 金級距)・獻祭費 1~10 金 |

觀察到的張力:

- **早期極緊**:一天做滿也就十幾金,一名祭品可能就 30 金。第一隻魅魔要存好幾天
- **看板娘第 2 位 50 金**是硬牆,實質上早期只能有一位
- **成長全靠獻祭**:名額/格數/報酬都要吃掉一隻魅魔才長得起來,而養越深獻越賺 → 循環的核心張力在「養她」與「吃她」之間
- 待實測:第一隻魅魔的取得時間、擴充成長的速度、召喚師纏上的頻率會不會讓早期玩家還沒站穩就先失去她
